# HAL 位带启动兼容修复

2026-11-16

## 调查与实现前设计

原始 DEMO 位于用户提供的 `D:/desktop/CIMC_DEMO/DEMO1/CIMC_DEMO`。用当前内核直接载入其已编译 HEX，执行第764条指令后停在 `0x08000BCA`，诊断为未映射地址 `0x42470060`。MAP 将此位置归入 `HAL_RCC_OscConfig`，AXF反汇编和HAL源码确认该指令关闭 RCC PLLON，随后重新配置并开启PLL。临时仅增加标准地址转换后，同一份 HEX 可执行100万条真实指令，GPIOD 输出为 `0x3500`，SysTick 中断持续运行。

复杂度为大。实际涉及 `engine/simulator.py`、`tests/test_bitband.py`、独立验证固件、版本文件、打包默认版本、发行公告与验证记录等至少15个文件。H1命中跨文件更新，H6命中公共模拟器内核，H9命中发布版本配置。H2/H3/H4/H5/H7/H8/H10未命中，本次复用接口、依赖和安装流程。用户此前授权每次更新完整发布、更新本机软件和清理旧包，本次沿用该授权。

能力地图核对后复用真实ARM执行、外设 `_read`/`_write`、SysTick、GPIO、原理图接线和既有升级发布流程。新增外设位带地址转换，当前直接MMIO窗口无法接收HAL发出的别名访问。按 ARM Cortex-M4 TRM 3.7 实现字对齐32位别名读写，写入仅使用数据bit0，在一次回调内完成真实寄存器读改写，保留已有外设副作用。未知底层寄存器继续给出诊断。

使用固定跳过PLL初始化的方案会改变用户机器码的执行语义，因此采用标准外设别名映射。影响两个板卡共同使用的CPU地址空间，原始板卡网络、用户固件与工程格式均沿用现状。SRAM位带和其他芯片全部外设兼容属于后续独立范围。

主要风险是别名写入丢失同寄存器其他位、忽略既有设备通知或对未知外设返回成功。通过独立真实机器码、位保留测试、未知目标故障测试及V1/V2全量回归验收。发布使用新版本0.5.1，源码标签和安装包保持一致。

## 验收标准

- 原始用户HEX在V1实际执行启动、HAL时钟初始化和SysTick，按PD8至PD13连接LED1至LED6后得到亮、灭、亮、灭、亮、亮。
- 已读取运行中客户端工程，原有六根跳线恰好按PD8至PD13顺序连接LED1至LED6，升级后恢复该工程。
- 独立探针证明PLL别名写入、读取0/1、单bit保留、bit0写入语义和未实现目标故障。
- Windows和Linux内核测试、冻结包及安装升级通过。
- 更新公告、GitHub源码、各平台软件及更新接口同步，成功后清理旧分发包。
