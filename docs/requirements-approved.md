# CIMC 2026 工业嵌入式纯仿真 EXE 需求与方案审批稿

- 文档版本：V0.1
- 日期：2026-11-15
- 状态：待用户审批，未进入软件实现
- 用途：汇总本次聊天中的需求、范围调整、建议方案与验收条件，作为后续开发依据。
- 说明：本文中的“支持”“实现”描述目标能力，不代表功能已经开发或验证完成。用户要求、建议方案和待核验信息分别标注。

本项目目标是制作一个 Windows 桌面仿真软件，直接运行 Keil 生成的 HEX/BIN 固件，在窗口内呈现原开发板的 OLED、LED、KEY 和串口交互。原板全部固定连线保持不变；用户只在实际存在的排针之间增加或删除自己添加的虚拟杜邦线。当前采用纯仿真方式，不纳入外接扩展板。

## 2. 软件目标与操作流程

目标体验：打开软件，载入固件，按原板排针接线，操作虚拟按键或发送串口数据，观察 OLED、LED 和串口回复。

建议操作顺序：

1. 打开软件，加载已经核验的板卡配置。
2. 导入 HEX 或 BIN；BIN 需要提供与固件链接设置一致的装载地址。
3. 查看原板固定电路，并在开放的排针引脚之间添加虚拟杜邦线。
4. 启动固件，按下、保持或松开虚拟 KEY，或者通过内置串口面板发送数据。
5. 观察固件驱动的 LED、OLED 和串口返回内容。
6. 使用运行、暂停、复位功能；按需要保存跳线方案和日志。

其中运行控制、接线保存、日志导出为配套功能建议，随本稿一并审批。

## 3. 当前功能范围

### 3.1 核心范围

| 模块 | 目标行为 |
|---|---|
| 固件执行 | 执行 Keil 生成的 HEX/BIN，从复位入口运行固件，响应其实际寄存器访问 |
| 主板固定电路 | 保留原理图全部原有连线、器件连接和排针映射 |
| 虚拟排针接线 | 仅在原板实际存在的排针引脚之间添加、删除用户自己的虚拟跳线 |
| KEY | 支持按下、持续按住、松开；电平由原电路及新增跳线决定 |
| LED | 亮灭由实际网络、电平、有效极性及固件输出共同决定 |
| OLED | 解析固件发出的显示命令和数据，在 Windows 窗口内显示像素结果 |
| 串口 | 在软件内部模拟 RS232、RS485、CH340 对应的通信通道 |
| 基础外设依赖 | 按测试固件实际需要实现 GPIO、时钟、定时、中断、USART、I²C 等支持；具体清单通过固件访问验证确定 |

### 3.2 当前不纳入

- 外接扩展板：外接 DC-DC 电源板、PT100 温度采样板、精密电阻模拟板及外置工业信号采样板。
- 真实硬件连接、真实 COM 口桥接、独立串口助手所需的虚拟 COM 驱动。
- CH340 的 USB 枚举、USB 驱动安装和 USB 电气行为仿真。
- 任意修改 MCU 引脚映射、拆除原板固定连线或重新设计底板电路。
- 精确模拟电源纹波、PCB 噪声、元件温升、器件损坏及 LED 电流和亮度。
- 在没有逐项验证的情况下，承诺任意 GD32 固件或全部竞赛任务均可运行。

上述排除的是本期功能开发，不会从原板固定电路中删除对应的原有器件和连线。固定拓扑的保留与外设行为是否已经实现是两个不同状态；访问尚未支持的外设时应给出明确诊断。

### 3.3 曾讨论但尚未确定纳入第一版的功能

板载 ADC 滑块、DAC、RTC、内部 Flash 擦写、板载外部 Flash、TF 卡、休眠、Bootloader/IAP、完整 Modbus 测试集、源码级调试及自动测试报告，均属于后续可选项。内部程序存储器的固件装载与取指属于核心运行条件，不受此处“Flash 擦写可选”的影响。

若上述某项是选定验收固件启动或运行的必要依赖，应在实现前明确其最小支持范围，不能通过静默跳过来宣称固件运行通过。

## 4. 固定电路与手动排针接线规则

这是本方案必须严格遵守的约束。

### 4.1 原板固定电路

1. 原理图中的全部原有连线构成不可修改的固定基线。
2. MCU 引脚与排针的对应关系、排针方向及脚序、同名网络、供电与地连接均按原资料建立。
3. 用户不能在软件中拆线、改线、重命名或重新分配这些固定连接。
4. 原板已经连接好的 LED、KEY、OLED 或串口电路，启动时即保持原连接；不为实现“手动接线”而人为拆开。
5. 若原资料指定默认跳帽或原有跳线状态，应记录并保留该初始状态，不擅自变更。
6. 不能仅根据外观照片推断电气连接，也不能用其他版本的板图直接代替选定版本。

### 4.2 用户新增的虚拟杜邦线

1. 连线端点只能选择原板实际暴露的排针引脚。
2. 新增跳线是在固定电路上增加连接，不会替换原有线路。
3. 用户只能删除、移动自己添加的跳线；原板已有连接仍保持不变。
4. 同一固定网络上的多个排针引脚，本来就应互相连通，不依赖用户重复接线。
5. LED、KEY 是否需要新增跳线，由原板实际连接关系决定。
6. 如果新增跳线与原电路共同形成电源短接或输出争用，应报告冲突；不将冲突状态伪装成正常的高低电平。
7. 悬空输入应有明确状态或提示，不统一强制为固定逻辑值来掩盖接线问题。

关系示意如下。它表达固定网络和附加跳线的层次，不表示所有 LED、KEY 都必须额外接线：

```text
原板固定网络：MCU ↔ PCB 原有走线 ↔ 实际排针及原有器件电路
                                      ↕
                         用户新增的虚拟杜邦线
                                      ↕
                            另一实际排针引脚
```

关键验收要求：用户新增或删除跳线后，原板固定网络清单与初始版本完全一致。

## 5. OLED 显示方案

OLED 画面由固件实际发送的命令和数据产生，不依赖在 Windows 中预设文本来替代固件显示逻辑。

```text
HEX/BIN 执行
    → GD32 I²C 外设或 GPIO 操作
    → OLED 通信与控制器模型
    → OLED 显存与像素
    → Windows 显示区域
```

- 固件中的文字、数字、汉字字模和图形数据应反映到虚拟屏幕。
- 原始像素显示、整数倍放大、截图为建议配套功能。
- 硬件 I²C 驱动需要相应寄存器和状态机支持；软件模拟 I²C 驱动需要 GPIO 电平与总线边沿解析，两者不能相互替代。
- 控制器型号、屏幕分辨率、通信接口、地址和引脚映射均需由所选板卡资料及驱动确认。当前 SSD1306/I²C 只是前期资料线索，尚未作为最终板卡事实锁定。
- 对初始化、寻址、写显存、开关屏等命令的支持，应按实际驱动列出并测试。

## 6. 纯仿真串口方案

串口面板与仿真中的 MCU 通信，整个过程在软件内部完成。

```text
内置串口面板发送
    → 对应通道的输入模型
    → MCU USART 接收与固件处理
    → MCU USART 发送
    → 内置串口面板显示回复
```

| 通道 | 仿真重点 | 约束 |
|---|---|---|
| RS232 | 数据收发、串口参数、状态标志和实际固件用到的中断 | 对应 USART 和固定接线必须按原板确认 |
| RS485 | 数据收发及板卡实际采用的收发方向控制 | 若为 GPIO 控制 DE/RE，需要保留该控制行为；若为自动方向电路，按其功能建模，不凭空新增控制脚 |
| CH340 对应通道 | 模拟 CH340 所连接 MCU 串口的数据传递 | 不创建真实 CH340 USB 设备，不要求 CH340 驱动 |

配套功能建议：ASCII/HEX 输入与显示、收发时间戳、波特率与校验参数设置、清空与保存日志。

三个界面入口不意味着主板上存在三个互相独立的 USART。若原电路有共用 USART、复用或互相影响的连接，仿真必须保留这些关系。数据回复必须由固件生成，界面不能自动生成预设“正确回复”冒充固件执行结果。

串口支持不等于自动实现 Modbus 或官方赛题协议。协议处理首先由载入固件决定，专门的协议测试面板另行确定。

## 7. 建议技术路线与交付方式

以下为建议方案，尚未通过实际固件验证，也未作为用户已经批准的技术选型。

| 层次 | 建议方式 | 主要工作 |
|---|---|---|
| Windows 界面 | C# WPF | 板卡显示、排针跳线、OLED 像素、按键操作和串口面板 |
| 固件执行框架 | 优先评估 Renode | 复用处理器执行、总线、内存及调试框架 |
| MCU 模型 | GD32F470 专项适配 | 按资料实现固件实际访问的寄存器、时钟、GPIO、中断和串行外设 |
| 板级模型 | 原板固定网络与器件模型 | 固定引脚映射、原电路连接及新增跳线的连通计算 |
| 显示模型 | 按已确认的 OLED 控制器适配 | 接收命令、更新显存并输出像素 |
| 交付 | 安装 EXE 或含主 EXE 的便携目录 | 将运行依赖和板卡配置随软件提供 |

本稿不采用将用户 C 代码改写为电脑程序来替代 HEX/BIN 执行的方案；也不采用与固件无关的预设 OLED/LED 动画作为验收依据。

HEX 自带装载地址，需要检查文件完整性、地址范围和启动信息；BIN 不包含装载地址，应按固件链接配置明确填写。带调试信息的 AXF/ELF 可作为后续调试增强，不能承诺仅凭 HEX/BIN 恢复 C 源码和变量名。

“提供 EXE 启动入口”与“全部依赖只有一个物理文件”不同，后者尚未被用户要求。最终安装形式待审批确定。
