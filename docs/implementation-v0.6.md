## 现状与资料

现有 `engine/simulator.py` 的时钟源为按已执行指令推进的SysTick功能模型，外部中断已有USART与NVIC路径。GPIO网络由原理图固定连接和可编辑跳线共同形成。`rg` 搜索 `timer|TIMER` 覆盖engine目录，现有外设模块尚无TIMER0～13计数、捕获比较或PWM行为。

官方 GD32F470xx Datasheet Rev2.2 的3.10节列出14个TIMER、24位SysTick和FWDGT/WWDGT。TIMER1/4为32位，TIMER0/7为16位高级定时器，TIMER5/6为基本定时器，TIMER8/11有两个通道，TIMER9/10/12/13有一个通道。RTC日历属于3.11独立章节。本次范围采用3.10定时器清单。

已取得官方 GD32F4xx User Manual Rev3.5 与Datasheet Rev2.2，存于 `artifacts/timer-reference`。用户工程附带的官方固件库 `gd32f4xx_timer.h/.c`、`gd32f4xx_rcu.h/.c` 和CMSIS中断枚举用于交叉核对地址、时钟位、向量及寄存器语义。

## 能力复用与实现

- 扩展真实ARM执行、NVIC、RCU、GPIO网络和位带访问，定时器寄存器由真实固件配置。
- 新增按硬件实例能力区分的TimerBank，覆盖全部14个实例。计数、预分频、影子装载、更新、比较、PWM、捕获、编码器、外部时钟、主从触发及高级输出保护产生实际可观察事件。
- 新增FWDGT和WWDGT模型，按独立IRC32K或APB时钟推进，产生复位或提前唤醒中断。
- 统一使用确定性的HCLK时间基准，保留V1/V2既有每条指令推进量。按事件截止时间批量推进外设，未使用定时器的固件保持轻量调度路径。
- 共享中断向量由各定时器真实标志和使能共同决定。NVIC优先级和嵌套异常依据寄存器配置调度。
- GPIO复用引脚依据官方AF表，PWM和捕获经过实际网络连接。固定铜线继续按两版原理图执行。
- 界面新增只读定时器状态页，显示实例、计数、周期、预分频、通道状态和中断。配置入口沿用固件寄存器写入。
- TIMER触发事件接入已有ADC/DAC支持的转换通路。DMA请求与DMA控制器边界在实际验收记录中逐项说明。

纯寄存器存储方案的评估结果是无法产生计数、通道边沿及真实中断，本次采用具有事件调度的外设模型。芯片每类定时器按其真实位宽和通道能力处理。

## 验收与风险

各实例必须通过独立Keil机器码执行的计数和中断测试，覆盖时钟门控、外设复位、共享向量、32位溢出及边界。专项回归覆盖预装载、rc_w0标志、单脉冲、中心对齐、PWM、捕获回接、编码器、触发链及保护行为。不同指令分块必须得到相同CPU和外设结果。

时钟分频和分数周期累积必须保持确定性，GPIO读改写、位带写入与外设事件共享同一时间点。重点检查同时到达的中断、主从触发回路、断线及输出冲突、看门狗复位和高频计数对界面响应的影响。

最后执行现有V1/V2及用户DEMO回归、冻结包、原生安装、同一Linux发行包补验，完成GitHub及Packages发布、真实软件内更新、公告与旧分发清理。实际结果逐项写入验收记录。
