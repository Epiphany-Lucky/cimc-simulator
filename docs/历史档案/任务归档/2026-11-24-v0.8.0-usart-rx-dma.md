# 0.8.0 串口接收 DMA

用户要求将 DEMO4 验证中缺少的 DMA 模型加入 CIMC Studio。以原版 HEX 使用的 USART 接收为交付目标。该项目每次产品更新均执行 `AGENTS.md` 的发布和分发验收流程。

## 复杂度与设计

| 硬条件 | 是否命中 | 依据 |
| --- | --- | --- |
| H1 涉及至少五个文件 | 是 | 涉及仿真内核、寄存器回归、位带探针、版本配置和发布文档 |
| H2 数据库 | 否 | 在现有仿真实例内管理 DMA 状态 |
| H3 对外接口 | 否 | 使用现有工程和串口命令及返回结构 |
| H4 权限 | 否 | 沿用现有本地仿真访问和发布权限 |
| H5 资金或订单 | 否 | 串口外设仿真 |
| H6 公共模块 | 是 | `engine/simulator.py` 提供两版板卡共享内核和 NVIC |
| H7 依赖 | 否 | 复用 Python 标准库与 Unicorn |
| H8 跨端协同 | 否 | 网页只同步版本号，现有串口交互协议可复用 |
| H9 构建与部署 | 是 | Windows、Linux、HTML 构建和发布入口同步版本 |
| H10 口径未确定 | 否 | 用户提交的 DEMO4 明确使用 `HAL_UARTEx_ReceiveToIdle_DMA()` |

产品和发布合计超过十五个文件，按大任务检查能力地图。旧版确切故障是对 `0x40026440` 读访问未实现。新增独立 DMA 寄存器设备，复用两版串口的接线、参数与队列，复用 Unicorn SRAM 及 NVIC 请求。原型仅覆盖一个固定配置，整合采用官方两个控制器、16 路寄存器和 USART 接收请求映射，便于同类固件复用。终端收到的字节由固件动态决定缓冲区和接收长度，回显仍由固件执行。

风险集中在 DMA 完成与 IDLE 到达同一批数据、清除中断后重挂，以及原有 RXNE 收发。检验通过长度边界、含零字节的满缓冲区和逐中断追踪覆盖。若需回滚，可还原该版本的 Git 提交并使用既有分发流程。发送 DMA、其他外设请求、内存复制和 DMA FIFO 等需各自验证。

执行证据见 [0.8.0 验收](../../validation-v0.8.0.md)。
