# 串口终端参数设计

用户要求检查 DEMO3 的串口输出，并为终端提供可自行选择的波特率等配置。本轮以 CIMC Studio 0.7.0 交付。

## 复杂度与现状

G1 判定为大。H1 涉及前端、仿真器、测试和分发共 15 个以上文件。H2 无数据库结构变更。H3 扩展既有命令、状态与工程格式。H4 无权限变更。H5 无资金业务。H6 扩展共用仿真器及界面状态。H7 沿用现有依赖。H8 涉及前后端协同。H9 同步既有打包版本配置。H10 用户已指定终端可配置，具体值和校验均属本轮实现决策。

- `web/index.html` 中的串口终端已有通道、ASCII/HEX 和 H6 接口选择。`web/app.js` 按通道过滤终端记录。
- `engine/simulator.py` 的 `_uart_path`、`_uart_transmit_enabled` 和 `command` 已处理固定网络、GPIO 复用、RS485 方向及 USART 收发。原收发路径未比较串口帧参数。
- DEMO3 最新链接映射含 `key_proc → my_printf → HAL_UART_Transmit`，机器码执行时 KEY1 触发 `HELLO\r\n`，原串口日志通道为 `ch340`。较旧的同名 HEX 的映射显示链接器移除 `HAL_UART_Transmit`，同一 KEY1 操作只翻转 LED2。

## 能力复用与实现范围

G2 核对既有能力地图。共用界面扩展现有终端和原生对话框，状态沿用 `/api/state`，设置沿用 `/api/command`。复用仿真器的通道路由、收发队列、诊断和工程预检。没有数据库、鉴权或新软件依赖。用户的本轮实现指令与既有发行约定涵盖本次开发、验证及发行。

每个实际映射通道可单独选择自动或手动。自动模式沿用既有收发语义并展示运行时参数。手动支持常用或自定义波特率、7/8 数据位、无/奇/偶校验和停止位。从 `USART_BAUD/CTL0/CTL1` 与实际 APB 时钟推导固件帧格式。固件启用校验时，校验位占据硬件字长的最高位。手动模式按 3% 相对波特误差及完全一致的帧格式检查双向数据。3% 是功能模型的比较阈值。

寄存器字长、校验位和 OVER8 的解释参照芯片资料。[GD32F4xx 用户手册下载](https://www.gd32mcu.com/en/download/6?kw=GD32F4xx) · [STM32F427 RM0090](https://www.st.com/resource/en/reference_manual/dm00031020-stm32f405-415-stm32f407-417-stm32f427-437-and-stm32f429-439-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf)

`serial_settings` 接收通道及配置，`null` 恢复自动。`serialSettings` 随工程 v3 保存并在导入时校验，旧工程默认自动。固件复位与同板重新烧录保留配置，切板重置为自动。原通道的物理连线继续由板卡配置管理。

仅改变界面标签会导致手动参数无法影响收发，因此在 MCU 实际读写路径校验。仿真范围为字节级异步串口，不增加真实 COM 口、硬件流控、9 位数据通道或电气波形模型。固件的寄存器配置始终由固件自身执行。

## 验收

验证实际 DEMO3 `HELLO` 的自动及 115200/8N1 手动接收、对照旧 HEX、波特率和格式不匹配时的提示，并验证用带应答的内置固件完成终端至 MCU 的匹配与拦截。验证独立通道、自动恢复、错误参数拒绝、旧工程兼容及工程重开。发布沿用双平台完整打包、原生安装、同包 WSL、真实应用内更新、Packages 回拉摘要和旧分发清理。

## 发布前发现 V1 接收中断中止

用户在 21:11 新编译的 DEMO3 中报告停止。已从实际 0.6.1 会话读取原诊断、固件及 12 条跳线。运行 7102 条指令后，PC `0x080019AC` 位于 HAL 的 `UART_Start_Receive_IT`，启用 RXNEIE 时，V1 的旧寄存器保护分支会报错并停止。V2 此时已经使用 `_refresh_uart_irq` 把 RXNE/IDLE 送入现有 NVIC。

本增量只放开 V1 的 RXNE/IDLE，并复用原有路由、状态寄存器、接收 FIFO、异常进入与中断返回。TXE/TC 发送中断和 DMA 仍由原诊断覆盖。验证内容包含 V1 真实 ARM 中断处理，和用户同一份故障 HEX 在 CH340 下接收短帧、发回内容以及继续处理 KEY1。
